# Threat Model

_Status: initial threat model for the local history vertical slice_
_Updated: 2026-08-21_

## Security objectives

1. Content the policy rejects must not reach persistent storage, FTS, thumbnails, logs, exports, sync or MCP.
2. No clipboard content leaves the Mac unless the user enables and invokes a clearly identified network feature.
3. Capture, automatic paste and future global text expansion request only their necessary permissions and have safe degraded modes.
4. Malformed or huge clipboard input must not corrupt the store or indefinitely block the UI.
5. Stored history must remain consistent across crashes, migrations, deduplication, retention and attachment cleanup.
6. Future adapters (Vault, sync, MCP, semantic search) cannot bypass the same authorization and sensitivity policy.

## Non-goals and honest limits

The initial regular history is local plaintext SQLite plus local attachment files. It relies on the signed-in macOS account, app sandbox/container permissions and FileVault for the primary at-rest boundary. It does **not** protect against:

- malware or another process running with the user's privileges and sufficient access;
- an administrator/root or physical attacker with an unlocked/decrypted Mac;
- content already exposed by the source/target application;
- every secret whose producer omitted markers and whose text evades heuristic detection;
- forensic recovery guarantees after deletion on SQLite/WAL/APFS/SSD storage;
- arbitrary third-party screen capture while previews are visible;
- a target application mishandling content after paste.

The future Vault has stronger goals and requires a separate design review. “Local” must never be presented as equivalent to “encrypted.”

## Assets

- clipboard text, rich text, images, screenshots, files/paths and original representations;
- OCR output, thumbnails, titles, notes, tags and search terms;
- source application and usage metadata;
- collections, saved queries, queues and bundles;
- database, WAL/SHM, attachments, backups/exports and migration copies;
- capture exclusions, retention and network settings;
- future Vault keys, sync credentials and MCP client grants;
- UI confidentiality while locked/presenting.

## Trust boundaries

```text
Untrusted apps/users ─▶ global NSPasteboard ─▶ capture policy ─▶ in-memory pipeline
                                                      │
                                              persistence boundary
                                                      ▼
                                  SQLite/WAL/FTS + attachment directory
                                      │          │           │
                                      ▼          ▼           ▼
                                     UI      export/sync    future MCP
```

- Pasteboard producers are untrusted, including friendly apps with bugs.
- Community marker types and source bundle IDs are untrusted hints.
- The database/attachment store is trusted only after validation; files can be corrupt or externally modified.
- Link origins, external AI providers, sync services and MCP clients are separate network/authorization boundaries.
- UI output can leak to shoulder surfers, notifications and screen sharing.

## Adversaries and failure actors

- a benign password manager whose marker support is incomplete;
- a malicious/local app placing secret-shaped, huge, malformed or rapidly changing data on the pasteboard;
- a background helper spoofing a source bundle ID;
- another local process reading app files or connecting to a future local service;
- an unauthorized MCP client or a compromised authorized client;
- a remote server receiving a URL-preview/AI/sync request;
- a curious person viewing the screen, notifications, backups or exported archives;
- application crashes, power loss, disk-full, migration bugs and database corruption;
- contributor mistakes that log content or route sensitive data into an index.

## Threats and mitigations

### T1 — Passwords/tokens are retained

**Examples:** password-manager copy, API key, JWT, private key, recovery codes, credit card, `.env` assignment.

**Mitigations:**

- reject `ConcealedType`, `TransientType`, `AutoGeneratedType` and known vendor markers before payload persistence;
- ship suggested ignored bundle IDs for password/keychain managers, visibly editable;
- run versioned local detectors for private-key blocks, common token prefixes/entropy patterns, JWT structure, credential assignments and payment-card candidates with checksum where applicable;
- default action for a positive high-confidence result: do not persist; show a content-free status and allow explicit one-time override/manual save;
- never log matching substrings, complete hashes, previews or detector internals that reveal the value;
- unit-test false positives and false negatives and document that detection is heuristic.

**Residual risk:** markers are optional, source attribution is fallible and detectors cannot recognize all secrets. Ignored apps reduce risk but are not a security boundary.

### T2 — Image/screenshot secrets leak through OCR

**Mitigations:**

- bounded in-memory quarantine for images while OCR/sensitivity analysis runs when strict scanning is enabled;
- no disk-backed temp/quarantine plaintext;
- size/time/error outcomes follow ADR 0002: the default is fail closed and skip; an explicit one-time manual override may accept an unscanned image without pretending it was classified;
- only commit image, OCR, thumbnail and search row after policy accepts them;
- never index OCR for skipped/Vault content.

**Residual risk:** OCR can miss visible secrets and large in-memory images can pressure memory. The accepted fail-closed default reduces persistence risk but can reject legitimate images.

### T3 — Exclusion rules are bypassed by source misattribution

**Mitigations:**

- prefer a declared `org.nspasteboard.source` when present but label it cooperative/unverified;
- separately store frontmost-at-detection inference;
- inspect type markers and content policy regardless of source;
- make manual mode, pause and ignore-next globally reachable;
- do not claim ignored applications are foolproof.

**Residual risk:** macOS exposes no authoritative writer identity. A background process can be misattributed or spoof metadata.

### T4 — Oversized/malformed payload denial of service

**Mitigations:**

- request only supported UTTypes;
- per-representation, per-item and aggregate limits;
- dimensions/pixel-count and decompression limits before full image decode where formats allow;
- bounded capture/OCR queues with cancellation/backpressure;
- no parser/OCR/thumbnail work on UI/poll callback;
- timeouts and failure counters; repeated failures pause visibly;
- fuzz/property tests for classifiers/query parser/transforms and malformed fixture corpus.

**Residual risk:** `NSPasteboard` cannot always reveal byte size before data is materialized; provider callbacks can block. Snapshot behavior needs adversarial integration tests.

### T5 — Wrong-app paste or clipboard race

**Mitigations:**

- retain exact target application before panel presentation;
- after dismissal, activate only that target and verify activation within a short timeout;
- if target quit, focus changed intentionally, permission is absent, or confirmation fails: copy only;
- mark self-writes so capture ignores them;
- leave selected content on clipboard rather than racing to restore an older value;
- test Spaces, full-screen, modal windows, secure fields, keyboard layouts and rapid focus changes.

**Residual risk:** target apps can ignore/redefine Paste, and synthetic events can fail. Clipboard contents are globally visible to other apps while present.

### T6 — Search/index/WAL leakage

**Mitigations:**

- policy acceptance precedes the first database transaction;
- no sensitive match detail in rows;
- normal history and Vault use separate security/index domains;
- short transactions, controlled backups, no ad-hoc DB copies;
- crash/diagnostic logging redacts SQL arguments, query text and snippets;
- disable SQL tracing in release builds;
- make support bundles opt-in and metadata-only by default.

**Residual risk:** accepted normal-history text exists in SQLite, FTS and WAL. FileVault/user-account security is the v1 protection.

### T7 — Attachment path traversal, substitution or orphan leaks

**Mitigations:**

- derive paths from validated hex digests; store relative paths only;
- standardize/rescope and verify every resolved path remains under the attachment root;
- private permissions, no following attacker-controlled symlinks, atomic temp-write/rename;
- verify SHA-256 before use/export/backup;
- DB references commit after file creation; grace-period orphan reconciler handles crashes;
- delete only when no DB references remain.

**Residual risk:** file and DB transactions cannot be one atomic operation; reconciliation is required.

### T8 — Database corruption/migration data loss

**Mitigations:**

- GRDB transactional append-only migrations;
- full fixture matrix and injected-failure tests;
- pre-migration online backup for destructive/large changes;
- foreign-key, integrity and FTS checks;
- capture disabled until DB and security settings open successfully;
- preserve damaged files and provide recovery/create-new-store paths.

**Residual risk:** disk failure and severe corruption can lose accepted local history. Portable verified backups are a user-owned-data requirement.

### T9 — Network exfiltration

**Mitigations:**

- no telemetry and no core network dependency;
- link preview fetching off by default and labeled because it contacts the copied origin;
- sync/AI adapters opt-in, named, cancelable and invocation-transparent;
- BYOK secrets in Keychain; never send content on configuration/test without explaining it;
- network code cannot accept raw `ClipStore`; it receives policy-filtered bounded values through an authorization service;
- privacy activity log stores destination/action/clip ID and time, not clip plaintext.

**Residual risk:** any user-enabled remote operation reveals content and network metadata to its provider.

### T10 — Screen/notification disclosure

**Mitigations:**

- panic hotkey hides all panels/windows immediately;
- manual Privacy Shield masks previews and suppresses preview-bearing notifications;
- sensitive/Vault previews masked by default and require explicit reveal;
- no clip text in notification body by default;
- clear VoiceOver announcements must not unexpectedly read masked content;
- document screen-sharing controls as best effort only.

**Residual risk:** no public API reliably prevents arbitrary modern screen capture or detects every active share.

### T11 — Future Vault cryptographic failure

**Required design constraints before implementation:**

- use CryptoKit authenticated encryption or an audited whole-database solution; no custom cipher/protocol;
- random DEK, versioned envelopes, unique nonces and AAD binding identity/schema/type;
- key material in Keychain with explicit Touch ID/user-presence and recovery policy;
- automatic relock on timeout/sleep/screen lock/fast-user-switch;
- no Vault plaintext in normal DB/FTS/WAL/thumbnails/Quick Look/logs/backups;
- define capture behavior while locked—never silently stage plaintext;
- acknowledge Swift/process memory cannot guarantee perfect zeroization.

**Blocking design choice:** plaintext FTS is incompatible with row-encrypted searchable text without recreating a plaintext index. Choose whole-database encryption, no locked search, or a deliberately separate ephemeral index after unlock.

### T12 — Future MCP unauthorized access

**Mitigations required before implementation:**

- disabled by default;
- prefer client-launched stdio bridge and narrow app IPC over a listening socket;
- explicit per-client grants: search metadata, read content, create clip, modify collections; deny Vault/sensitive access initially;
- bounded results, byte/page/query limits, timeouts and cancellation;
- app authorization service enforces lock/sensitivity policy; helper never opens DB/Keychain directly;
- revocation and content-free audit events;
- if HTTP is unavoidable: loopback only, strict Host/Origin validation, random bearer credentials, rate limits, current MCP auth requirements, no trust in localhost alone.

**Residual risk:** an authorized client can exfiltrate the content it is allowed to read. Client identity/installation can be spoofed without a careful pairing model.

### T13 — Optional text expansion captures keystrokes

**Mitigations required before implementation:**

- feature disabled until explicitly enabled;
- explain Input Monitoring and Accessibility separately;
- match only configured abbreviations with minimal rolling in-memory state;
- never persist raw keystroke streams;
- suspend during secure input/password contexts where detectable and offer per-app exclusions;
- no expansion of Vault/sensitive clips initially.

## Privacy defaults

Proposed defaults requiring product confirmation:

- capture enabled only after clipboard onboarding/access;
- 30-day retention; pinned clips exempt; automatic bounded cleanup;
- concealed/transient/autogenerated and known password-manager types rejected;
- high-confidence sensitive text rejected, not stored;
- link previews/network metadata fetch disabled;
- CloudKit, semantic indexing, MCP, screenshot folder monitoring and text expansion disabled;
- auto-paste unavailable until Accessibility is explicitly granted; copy-only works;
- no telemetry/crash uploader SDK.

## Security logging rules

Allowed:

- event category, coarse size bucket, UTI, elapsed time, success/error code, migration version;
- stable random operation IDs that do not derive from content;
- permission states.

Forbidden:

- clipboard text/images/paths/URLs;
- OCR output, titles, notes, tags and search queries;
- raw SQL arguments or FTS patterns;
- full content hashes for rejected sensitive values;
- Keychain values, auth tokens, MCP bearer values;
- unredacted file-system paths in automatic diagnostics.

Debug content logging must not exist as a hidden default. Any explicit developer diagnostic mode must warn, expire, remain local, and visibly indicate activation.

## Security test plan

- marker/vendor-type fixtures and ordering-before-read tests;
- secret detector positive/negative/adversarial corpus;
- ignored-app/source provenance spoof/misattribution tests;
- large data, image bombs, malformed RTF/HTML/SVG/JSON and parser fuzzing;
- no-persistence assertions across DB, FTS, WAL-facing transaction hooks, attachments and logs;
- wrong-target/focus race and permission-revocation tests;
- attachment traversal/symlink/checksum/orphan tests;
- migration crash/disk-full/corruption recovery;
- export manifest tampering and path traversal when archive format exists;
- MCP capability/revocation/replay/origin tests before MCP ships;
- independent security review before Vault or network-accessible MCP.

## Response and disclosure

`SECURITY.md` will define a private vulnerability reporting channel, supported versions and response expectations before public release. Security fixes affecting persisted secrets must include migration/cleanup guidance and candid residual-leakage notes; silently deleting history is not an acceptable response.

## Accepted defaults and remaining security decisions

ADR 0002 accepts fail-closed unscannable-image handling, favorite/pin retention exemption, and initial payload/disk ceilings. ADR 0001 accepts the initial sandbox/source-first distribution posture.

Remaining future stop point: Vault searchable-encryption and locked-capture behavior. Vault remains unimplemented until it receives a separate reviewed design.
